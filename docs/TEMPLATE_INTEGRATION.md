# اتصال محتوای جدید به قالب دقیقِ قبلی

قالب مرجع، فرم طلاییِ Stitch14 با جدول بومی Word، لوگو و جمع‌هاست؛ مبنای خروجی **DOCX→PDF از همان DOCX** است، نه دو رندر مستقل. این فایل مسیر و قرارداد تولید را مشخص می‌کند؛ ادعای تولید و تأیید فایل نهاییِ دانش‌آموز نیست.

## مرجع کدِ بازیابی‌شده
مخزن `danmillman008-hub/ketab-haye-darsi`، کامیتِ مشاهده‌شده در۱۸اکتبر۲۰۲۶:
`b9400eafc25bd1eb5d2f2c0f77b026c665619f34`.

- `stitch-14/scripts/build_planner_word.py`: چهار صفحه، سه روز در صفحه، شش خانهٔ محتوا در هر روز، جمعه جدا.
- `stitch-14/scripts/word_layout.py`: جدول بومی، A4، اندازه‌ها، راست‌به‌چپ، فونت تعبیه‌شده.
- `stitch-14/scripts/branding.py` و `ooxml_order.py`: وابستگی‌های مستقیم.
- `stitch-14/plan.json`: قرارداد دادهٔ محتوا.
- `stitch-14/scripts/render_word.mjs`: مسیر تبدیلِ خروجی Word؛ نیازهای محیطی‌اش پیش از اجرا کنترل شود.

برای دریافت با GitHub CLI، از مسیر API با `ref` همین کامیت استفاده کن. این شناسایی به معنی کپی شدن تمام renderer و دارایی‌ها به این مخزن نیست. بازتولید باید لوگو/فونت/قالب همان مرجع را بازیابی کند و حقوق دارایی‌ها رعایت شود.

## قرارداد دادهٔ هر روز
آرایهٔ روزها؛ هر عضو:

```json
{
  "week": 1,
  "day": 0,
  "name": "شنبه",
  "date": "تاریخ شمسیِ کنترل‌شده",
  "iso": "تاریخِ شمسی در قرارداد قدیمی؛ به موتور Gregorian نده",
  "boxes": [
    {
      "subject": "درس و پایه",
      "topic": "لقمه، موضوع و صفحهٔ تأییدشده",
      "detail": "نوع کار؛ منبع؛ مدت و تحلیل؛ معیار اتمام",
      "hours": 1.25,
      "tests": 20
    }
  ],
  "hours": 1.25,
  "tests": 20
}
```

جمع روز از جمع باکس‌هاست؛ `tests=null` در مرحلهٔ پژوهش یعنی نامعلوم، نه صفر. پیش از خروجیِ نهایی تعداد را تعیین کن یا با «پس از کالیبراسیون» صریح نمایش بده؛ آن را بی‌اجازه به۲۰/۳۰ تبدیل نکن. تاریخ `planner.schedule` میلادی ISO است؛ `iso` در JSON قدیمی ظاهراً شمسی است. تبدیل باید صریح و کنترل‌شده باشد.

## خطر مهم: تغییر plan.json به تنهایی کافی نیست
در renderer بازیابی‌شده هنوز چند **ثابت محتواییِ قدیمی** وجود دارد:
- اهداف روز از زوج/فرد بودن روز، «زیست‌وریاضی/فیزیک‌وشیمی» ساخته می‌شود.
- عنوان و تاریخ جمعه، آزمون۱آبان و هفتهٔ تمرینی hard-code شده است.
- پانوشت می‌گوید تست زیست همیشه۲ساعت است.
- عنوان سند و نام خروجی ثابت است.

این موارد باید از ورودی جدید خوانده شوند، **بدون تغییر هندسه/لوگو/سبک قالب**؛ در غیراین‌صورت محتوای متغیر در فرم قدیمی با تیتر دروغین تحویل می‌شود. برای آزمون پنجشنبه، کار آزمون در همان روز واقعی ثبت شود؛ جمعهٔ جدا می‌تواند جبران/مرور یا وضعیت واقعی جمعه باشد، نه آزمون ساختگی.

شش خانه در روز سقف هندسیِ این قالب است، نه الزام به شش جلسه. اگر تسک‌ها بیشترند، زیرجلسه‌های هم‌درس/هم‌موضوع را در یک باکس با مدت و محتوای صریح ترکیب کن؛ اگر متن در ارتفاع ثابت جا نمی‌شود **حذف مخفی/ریزکردن نامحدود فونت ممنوع**. روز را سبک‌تر یا دامنهٔ پوشش را با علت اصلاح کن؛ گسترش قالب فقط با تصمیم صریح مجاز است.

## کنترل پیش از تحویل
۱. تمام نام/تاریخ/هدف/پانوشت از وضعیت جدید؛ هیچ ثابت۱آبان یا دو ساعت زیست باقی نماند.
۲. ساعت باکس، ساعت روز و ساعت هفته برابر دفتر تقویم؛ کلاس/خواب/تحلیل دوبار حساب نشود.
۳. Word با جدول بومی قابل ویرایش؛ PDF از همان Word؛ تعداد صفحه و فونت‌ها کنترل شود.
۴. رندر هر چهار صفحه با مرجع هم‌اندازه مقایسه شود: بیرون‌زدگی، بریدگی، فارسی، کادر جمع و لوگو.
۵. بستهٔ فعلی هنوز این QA بصری را برای خروجی جدید انجام نداده؛ این مرحله برای هر دانش‌آموز الزامی است.
